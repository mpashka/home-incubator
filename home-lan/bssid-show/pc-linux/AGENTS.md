# bssid-show (Linux PC) — правила для агентов

Приложение для этого ноутбука: показывает текущий BSSID, понятное имя домашней точки и уровень
сигнала; проводит обход контрольных точек и сохраняет данные для настройки Wi-Fi-роуминга.
Продуктовый контракт — [`docs/specifications/product.md`](docs/specifications/product.md).

   CSV и проверенные продуктовые решения, но не Android API и ограничения платформы.

## Границы задачи

- Показывать фактические BSSID/SSID/RSSI текущего Wi-Fi-соединения и комнату по карте точек.
- Снимать уровни **всех** видимых BSSID на контрольных точках, а не только текущего.
- Сохранять результат в формате, совместимом с Android CSV, чтобы анализ в `cfg` был общим.
- Результат передаётся в `home-config-secrets` для анализа и настройки мощности. Приложение
  само роутеры не меняет.
- Не нужны история, графики, темы, фоновый демон и абстракции «на будущее» до отдельного запроса.
- Нельзя показывать старый BSSID/RSSI как текущий: ошибка или устаревшее чтение видны явно.
- Проверять на реальном адаптере этого ноутбука; мок не доказывает сканирование и роуминг.

## Ponytail

Работаем со скиллом `ponytail:ponytail`, уровень `full`. До выбора языка или GUI сначала
проверь уже доступные Linux/NetworkManager-инструменты (`nmcli`, `iw`) и стандартную библиотеку.
Новая зависимость допустима только если без неё нельзя выполнить продуктовый контракт.
Сознательный компромисс помечай `ponytail:` с потолком и путём апгрейда.

## llm-wiki-tags

Реестр тегов — [`docs/tags.md`](docs/tags.md).

- У каждого значимого каталога есть `index.md`: одна строка на файл/подкаталог, ссылки вверх и вниз.
- Перед изменением иди по ближайшим `index.md` до нужного кода.
- Добавил, удалил, переместил или сменил назначение файла — обнови затронутые индексы.
- Сквозное понятие в коде и документации получает токен `@tag:<slug>`: в Markdown front matter,
  в коде — комментарий над элементом; тег регистрируется в `docs/tags.md`.
- Документация разделена по ответственности: `specifications`, `implementations`, `production`,
  `testing`. Исходные пользовательские запросы живут только локально в `docs/requests/` и
  никогда не коммитятся.
