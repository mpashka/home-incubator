# Устройство Android-приложения

Структура каталога — в [`index.md`](index.md). Проект собирается без Gradle утилитами Android
SDK (`aapt2`, `javac`, `d8`, `apksigner`) через [`../build.sh`](../build.sh).

## Код

- `java/org/mpashka/bssidshow/RoomWidget.java` — провайдер виджета: рисует по сохранённому состоянию и **сам Wi-Fi не читает** (`onUpdate` приходит в фоне, а в фоне BSSID недоступен).
- `java/org/mpashka/bssidshow/RefreshActivity.java` — прозрачная активность, открывается по нажатию на виджет: нужна ровно затем, чтобы процесс на мгновение оказался на переднем плане и чтение сработало.
- `java/org/mpashka/bssidshow/MainActivity.java` — главный экран: состояние, объяснение разрешений, карта.
- `java/org/mpashka/bssidshow/SurveyActivity.java` — `@tag:site-survey`, обход точек замера: маршрут приходит файлом снаружи либо, если файла нет, собирается из комнат в карте BSSID — имён точек в коде не зашито. Одна кнопка: после удачного замера переход к следующей точке автоматический, место в маршруте переживает выход. На каждой точке пишутся уровни всех видимых BSSID в CSV в `getExternalFilesDir()`. В конце файл можно отправить на одноразовый LAN-приёмник, на app-server либо позднее забрать через `adb pull`. Зачем это нужно и как обрабатывается — `home-config-secrets @/ansible/docs/wifi.md`, «Замеры с телефона».
- `java/org/mpashka/bssidshow/Upload.java` — `@tag:survey-upload`, общий HTTP PUT файла: открытый для временного LAN-приёмника, с клиентским сертификатом из `KeyChain` для app-server.
- `java/org/mpashka/bssidshow/Wifi.java` — `@tag:bssid-read`, чтение SSID/BSSID/RSSI и разбор причин отказа.
- `java/org/mpashka/bssidshow/Rooms.java` — `@tag:ap-map`, карта BSSID→комната и шкала dBm→палочки. Внизу файла самопроверка: `./build.sh check`.

## Ресурсы

- `res/drawable/ic_hall|ic_kitchen|ic_bedroom|ic_work.xml` — иконки комнат (дверь, кастрюля, кровать, портфель). Имена комнат сопоставляются с ними в `Rooms.icon()`.
- `res/drawable/ic_wifi.xml`, `res/drawable/ic_launcher_fg.xml` — значок приложения.
- `res/drawable/widget_bg.xml` — тёмная подложка виджета, чтобы иконка читалась на любых обоях.
- `res/layout/widget.xml` — 1x1: иконка стандартного размера 48dp + четыре палочки сигнала по нижнему краю. **Ловушка:** `RemoteViews` инфлейтит только фиксированный список классов, голого `View` в нём нет — одна такая строка валит всю разметку, и лончер показывает чёрный квадрат «не удалось добавить виджет». Причина видна только в `adb logcat` (`Class not allowed to be inflated`). Палочки поэтому `ImageView`.
- `res/layout/main.xml` — главный экран.
- `res/layout/survey.xml` — экран обхода и отправки CSV; после успеха форма скрывается, остаются подтверждение и кнопка повторной отправки.
- `res/values/strings.xml` — тексты и **карта точек по умолчанию** (`default_mapping`, снята с [`../docs/home-aps.md`](../docs/home-aps.md)); правится в приложении без пересборки.
- `res/xml/widget_info.xml` — описание виджета.

## Состояния виджета

| что видно | что это значит |
|---|---|
| встроенная иконка | BSSID найден в карте, и первое слово записи — известное имя комнаты |
| эмодзи | BSSID найден, но встроенной иконки под это имя нет: рисуется первое слово записи как есть. Так новая комната заводится данными, без пересборки |
| знак вопроса | BSSID прочитан, но такой точки в карте нет |
| восклицательный знак | прочитать не вышло: Wi-Fi выключен, нет подключения, нет разрешения, выключены службы геолокации. Причина — в описании для скринридера и на экране приложения |
| иконка притушена | показания старше десяти минут: то, что видно, могло устареть |
| палочки погашены | сигнала нет, состояние неизвестно **или** показания устарели — вчерашний уровень показывать как сегодняшний нельзя. Цветное эмодзи притушить нечем, поэтому палочки — единственный признак устаревания, видимый в обоих режимах |
