# Передача результатов замера

Родитель: [`index.md`](index.md).

Рабочий путь — одноразовый HTTP PUT на ПК `192.168.2.122`. Защита внутри доверенной домашней
LAN сознательно не добавляется: процесс живёт только до первого принятого файла, принимает
только имя `survey-YYYYMMDD-HHMM.csv` и ограничивает размер 10 МиБ.

## Как передать

На ПК из каталога приложения запустить:

```bash
./build.sh receive
```

Приёмник слушает `http://192.168.2.122:8765/` и складывает один файл в
`~/Projects/home/home-config-secrets/ansible/survey-results/`, после чего завершается.

На телефоне закончить обход, проверить адрес и нажать **«Отправить на ПК»**. Успех означает,
что ПК полностью записал файл и ответил HTTP 201. При любой ошибке исходный CSV остаётся в
каталоге приложения и его по-прежнему можно забрать через `adb pull`.

После успеха форма отправки скрывается, на экране остаются явное подтверждение и кнопка
**«Отправить ещё раз»**, которая возвращает форму.

Если IP или порт изменятся, адрес можно исправить прямо перед отправкой; приложение запомнит
его. Значение по умолчанию живёт в `app/res/values/strings.xml`, вывод приёмника — в
`receive-survey.py`.

Код app-server остаётся вторым действующим способом. Его кнопка появляется только если ранее
выбранный alias по-прежнему отдаёт приватный ключ и цепочку сертификатов из Android KeyChain.
На чистой установке кнопка скрыта; отдельный сценарий настройки сейчас не добавляется.

## Hold

Не реализованы, но сохранены как возможные запасные пути:

- Android Sharesheet через LocalSend или KDE Connect/GSConnect;
- Wireless ADB и автоматический `adb pull`;
- SMB, FTP, WebDAV или синхронизация каталога.

Возвращаться к ним стоит только если одноразовый PUT окажется неудобным или ненадёжным на
живом телефоне.
