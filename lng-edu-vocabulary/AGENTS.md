# Инструкции для ИИ-агента

Электронный словарь сербского языка: поиск по словоформам, ударения, связи с корнями,
пополнение через LLM.

## О проекте

- **Бэкенд**: Spring Boot, Java 25 (`/opt/java/jdk-25`), сборка Gradle
- **Фронтенд**: Vue
- **База**: Postgres
- **На будущее**: нативное приложение под разные ОС

Что словарь должен уметь: искать слово по любой его словоформе, показывать ударение
для слова и всех его словоформ, показывать разные значения слова раздельно, примеры
употребления, связь с русским / праславянским / сербским корнями.

## Правила работы

- **Язык документации и комментариев — русский.** Пользователь не любит англицизмов:
  если у термина есть понятный русский аналог — бери его.
- **План живой.** Перед задачей сверься с [docs/plan.md](docs/plan.md), после — отметь
  сделанное в том же изменении.
- **Правила проверяй на выборке.** Любой набор правил (часть речи, словоформы) должен
  сопровождаться прогоном на выборке из исходной базы и оценкой точности.
- 🚨 **Секретов в репозитории нет.** Пароль базы и ключи к моделям лежат в
  `secrets.properties` в корне — файл вне git; в git едет только
  `secrets.properties.template` с описанием ключей. Завёл новый секрет — тем же
  изменением добавь ключ в шаблон и строку в [README.md](README.md).
- **Не выдавай догадки за факты.** Формат исходной базы восстановлен обратной разработкой;
  где нет уверенности — пиши об этом прямо.
- **Никакой привязки к одному поставщику моделей.** Начинаем с Yandex, но обращения к
  модели идут через собственный интерфейс, а поставщик выбирается настройкой. Подробнее —
  [docs/implementation/llm.md](docs/implementation/llm.md).

## UX

**Правила взаимодействия** лежат в [`.claude/rules/ux/`](.claude/rules/ux/) — Claude Code
грузит их сам, остальные агенты читают их там же. Это соглашение
**ux-principles**, канон — `~/Projects/github/m_pashka/home-incubator/ux-principles/`
(в отдельный репозиторий пока не вынесено), в трёх слоях: `core` (любой
интерфейс), `desktop` (курсор, клавиатура, окна), `process` (как записать сценарий и
посчитать шаги), плюс `positions` — спорные позиции.

Собственные правила словаря, сценарии с числами шагов и описанные отходы —
[docs/specification/ui.md](docs/specification/ui.md), **и они важнее общих**. Отойти от
принципа можно, но отход записывается там, с причиной, а не правкой общего правила.

Коротко, что нарушают чаще всего: интерфейс проектируется от сценария, а не от списка
возможностей; шаги считаются из того состояния, где человек уже находится, и взвешиваются
частотой; действие живёт на объекте, а не в настройках; обратимое не подтверждают;
предупреждение висит, только пока есть что делать.

## llm-wiki-tags

В репозитории установлен [llm-wiki-tags](https://github.com/mpashka/llm-wiki-tags):
документация — читаемая LLM вики плюс тэги `@tag:<slug>`, связывающие код и документацию
поперёк дерева директорий. Каноническая формулировка правил лежит в
`.claude/rules/llm-wiki-tags/` (Claude Code подгружает их сам, остальным агентам —
читать оттуда же), реестр тэгов — [docs/tags.md](docs/tags.md).

Коротко:

- **`index.md` в каждой значимой директории**, ссылки двусторонние (родитель ⇄ потомок),
  у каждой детали одна страница-владелец — `wiki.md`.
- **Вся документация в `docs/`**: `specification/` (взгляд снаружи), `implementation/`
  (взгляд внутрь), `testing/` (как проверяется), `requests/<задача>/` (рабочие файлы
  задачи) — `docs-layout.md`.
- **Сначала читай, потом делай; обновляй по ходу.** Документация, разошедшаяся с кодом, —
  это дефект, а не пункт бэклога.
- **Тэгируй сквозные концепты**: сначала зарегистрируй тэг в [docs/tags.md](docs/tags.md),
  потом поставь токен в коде (комментарием над пакетом, файлом, классом или методом) и
  в документации (front matter, поле `tags`) — `tags.md`, `code-tags-java.md`,
  `code-tags-javascript.md`.

Поиск:

```bash
grep -rn "@tag:<slug>" .                      # все места тэга и его потомков
grep -oE "@tag:[a-z0-9/-]+" path/to/file      # тэги файла
grep -rhoE "@tag:[a-z0-9/-]+" . | sort -u     # все тэги репозитория
```
