# llm-wiki-tags — раскладка документации

Соседние правила: [`wiki.md`](wiki.md) (правила индексов), [`tags.md`](tags.md)
(тэги).

```
docs/
├── index.md                      # индекс документации
├── tags.md                       # реестр тэгов
├── specification/                # как программа выглядит снаружи
│   ├── index.md
│   ├── payments.md               # небольшая область: одна страница
│   └── payments/                 # разросшаяся область: директория со своим index.md
│       ├── index.md
│       └── retry.md
├── implementation/               # как она устроена внутри — та же форма
├── testing/                      # как тестируется: стратегия, тест-кейсы
└── requests/                     # рабочие файлы отдельных задач
    └── <task_name>/              # request.md, plan.md, отладочные скрипты, заметки
```

1. **Вся документация лежит в `docs/`.** В корне репозитория остаётся только то,
   что обязано там быть: `AGENTS.md`, `CLAUDE.md`, readme, лицензия и файлы,
   которые инструменты требуют в корне (`package.json`, `pyproject.toml`,
   `go.mod`, `Makefile`, конфиг CI, …). Больше ничего.
2. **`docs/specification/`** — как программа выглядит для внешнего пользователя:
   возможности, интерфейсы, форматы, поведение. **`docs/implementation/`** — как
   она устроена внутри. **`docs/testing/`** — как она тестируется, плюс
   тест-кейсы. Страница относится ровно к одному из трёх.
3. **Эти три дерева разложены по тэгам.** Тэг становится страницей
   (`docs/implementation/payments.md`) или, когда разрастается, директорией с
   `index.md` (`docs/implementation/payments/`). И тэги, и директории
   **иерархичны, иерархия предпочтительна**: `@tag:payments/retry` ↔
   `docs/implementation/payments/retry.md`.
4. **Называть файл по тэгу предпочтительно, но не обязательно.** У страницы
   обычно несколько тэгов; используй тэг в имени файла, только если этот тэг —
   основная тема страницы. Все тэги страницы попадают в её front matter
   независимо от имени файла.
5. **Рабочие файлы задачи — в `docs/requests/<task_name>/`**: постановка
   (`request.md`), план (`plan.md`), отладочные скрипты, черновые заметки. Это
   след одной задачи, а не часть постоянной вики: не оставляй такие файлы в корне
   репозитория и рядом с кодом.
6. **То, что переживает задачу, уезжает из `requests/`.** Если задача изменила,
   как программа выглядит, работает или тестируется, это знание тем же
   изменением попадает в `specification/`, `implementation/` или `testing/`;
   папка задачи остаётся историей, а не местом, куда ходят за справкой.
7. В каждой директории внутри `docs/` есть `index.md` (см. [`wiki.md`](wiki.md)).
