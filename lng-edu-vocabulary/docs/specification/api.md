# REST API словаря

Родительский индекс: [index.md](index.md) · Поведение оболочки: [ui.md](ui.md)

Бэкенд слушает `http://localhost:8180`. Фронтенд в разработке перенаправляет на него
всё, что начинается с `/api`.

Данные читаются из **Postgres** — словарь перенесён туда конвертером
(`./gradlew :importer:migrate`, см. [db-schema.md](../implementation/db-schema.md)).

## Поиск

```
GET /api/words?q={запрос}&limit={сколько}&alphabet={режим}&forms={true|false}
```

`q` — начало сербского слова (кириллицей либо латиницей), **любая его словоформа**
либо русский перевод. `limit` по умолчанию 20, не больше 100.

`alphabet` задаёт, что искать по алфавиту ввода: `separate` — кириллица ищет только
русский перевод, латиница — сербское слово; `any` — оба направления при любом алфавите;
`current` (по умолчанию) — кириллица ищет оба направления, латиница — сербское.

`forms` (по умолчанию `true`) — искать ли **по словоформам**. Выключенный поиск ищет
только по заглавному слову и переводу. Это разные способы искать, а не улучшение
одного: поиск по формам находит слово, которого в запросе нет ни одной буквой
заглавной строки, — «вода» приводит к `во̏д`, у которого это творительный падеж.

```json
{
  "items": [
    { "id": 41366, "name": "вода", "headword": "во̀да",
      "translations": ["вода́", "река́"], "matchedForm": null },
    { "id": 41364, "name": "вод", "headword": "во̏д",
      "translations": ["взвод"],
      "matchedForm": { "grammar": "ins.sg", "value": "водом" } }
  ],
  "total": 2
}
```

`id` — идентификатор слова; **по нему и надо открывать статью**, см. ниже. `name` —
написание статьи кириллицей без ударений.

`matchedForm` — форма, по которой слово нашлось, и её грамматическая помета. Заполнена
только тогда, когда совпало не само заглавное слово: если совпало оно, объяснять нечего.
Без этого поля непонятно, почему в ответ на «водом» пришло `во̏д`.

## Статья по идентификатору

```
GET /api/words/id/{id}
```

Основной способ открыть статью: щелчок по строке в списке найденного обязан привести
ровно в то слово, по которому щёлкнули. `404`, если слова с таким `id` нет.

## Статья по написанию

```
GET /api/words/{name}
```

`name` — написание кириллицей без ударений; в адресе кодируется
(`/api/words/%D0%B2%D0%BE%D0%B4%D0%B0`). Нужен для набранного руками адреса и для
ссылок на сербские слова внутри примеров.

**Заглавное слово сильнее словоформы.** Сначала ищется статья с таким написанием; поиск
по формам включается, только если такой статьи нет вовсе. `404`, если не нашлось ни так,
ни так.

## Ответ статьи

Оба обращения отвечают одинаково:

```json
{
  "matchedBy": "headword",
  "words": [ { "id": 41366, "name": "вода", "headword": "во̀да", "…": "…" } ]
}
```

`matchedBy` говорит, что произошло, а `words` — список карточек:

| `matchedBy` | Что нашлось | Что в `words` |
|---|---|---|
| `headword` | статья с таким написанием | **омонимы** — самостоятельные слова одного написания (`бити` — «быть» и «бить») |
| `id` | конкретное слово | оно и его омонимы того же написания |
| `form` | статьи с таким написанием нет, совпала словоформа | **разные слова**, у каждого свой `matchedForm` |

Различать эти случаи обязательно: `вод` и `вода` — не омонимы, и показывать их одной
статьёй значит врать о языке.

## Карточка слова

```json
{
  "id": 41366,
  "name": "вода",
  "headword": "во̀да",
  "headwordLatin": "vòda",
  "grammar": ["ж"],
  "partOfSpeech": "NOUN",
  "forms": [ { "form": "во̀де", "grammar": "gen.sg", "source": "RULES",
               "rule": "noun-declension", "ruleType": "FEMININE_A" } ],
  "roots": [],
  "senses": [
    { "number": 1,
      "translations": ["вода́"],
      "examples": [ { "serbian": "слатка во̀да", "russian": "пре́сная вода́" } ] }
  ],
  "idioms": [ { "serbian": "велика во̀да", "russian": "полово́дье, разли́в" } ],
  "status": "IMPORTED",
  "needsLanguageReview": false,
  "reviewReason": null,
  "homonymIndex": 1,
  "matchedForm": null
}
```

`number` равен `null`, если в исходной статье нумерации значений не было — таких
статей 72 %. `partOfSpeech` может быть `UNKNOWN`. `grammar` — пометы без завершающей
точки (`ж`, а не `ж.`); точка ставится при показе.

`forms` содержит известные словоформы с обозначением грамматики и источником; `RULES`
означает форму, полученную правилом и требующую языковой проверки. У таких форм `rule` —
ключ правила, а `ruleType` — его разновидность (тип склонения). По этой паре оболочка
показывает **правило целиком**: окончания, парадигму слова, примеры и исключения.

`roots` содержит связи с русским, сербским, праславянским, праиндоевропейским либо
другим корнем; сейчас таблица корней ещё не заполнена.

`needsLanguageReview` — по слову остались отложенные языковые пробелы, а `reviewReason`
перечисляет какие («значения не разделены», «часть речи не определена», «нет ударения»).
Таких слов 0,8 %; оттачивание качества отложено, см. [plan.md](../plan.md), этап 6.

Значения полей: `partOfSpeech` — `NOUN`, `VERB`, `ADJECTIVE`, `ADVERB`, `PRONOUN`,
`NUMERAL`, `INTERJECTION`, `CONJUNCTION`, `PREPOSITION`, `PARTICLE`, `UNKNOWN`;
`status` — `NO_TRANSLATION`, `IMPORTED`, `AWAITING_REVIEW`, `COMPLETE`.

## Пометы словоформ

Помета — внутреннее обозначение указателя, а не помета словаря: `nom.sg`, `gen.sg`,
`loc.pl` у существительных, `praes.1sg` у глаголов, `adj` у формы прилагательного, чей
род из статьи не следует. Русские и сербские названия к ним — на стороне оболочки
(`frontend/src/labels.js`), один владелец на весь показ.

## Ударения в ответах

Ударения приходят **комбинируемыми знаками Unicode**, то есть уже готовыми к показу,
а не служебными знаками исходной базы.

| Что | Знак | Пример |
|---|---|---|
| краткое восходящее | U+0300 | во̀да |
| долгое восходящее | U+0301 | ру́ка |
| краткое нисходящее | U+030F | бра̏т |
| долгое нисходящее | U+0311 | ма̑јка |
| заударная долгота | U+0304 | јуна̄к |
| русское ударение | U+0301 | вода́ |

У форм, порождённых правилом, ударения **нет**: оно с заглавного слова не переносится
(измерено — совпадает в 16,4 % случаев, см.
[word-forms.md](../implementation/word-forms.md)).

Русское ударение в исходной базе записано тем же символом U+2019, что и сербское долгое
восходящее; различить их можно только по помете фрагмента, поэтому преобразование делается
раздельно — `Serbian.renderAccents` и `Russian.renderStress`. Наружу отдаётся уже готовый вид.

Шрифт на стороне показа обязан покрывать эти знаки, иначе будут квадраты. Подходят
DejaVu Serif, Noto Serif, Liberation Serif.
