# Формат исходной базы сербско-русского словаря

Родительский индекс: [index.md](index.md)

Файл: `srbbase.db` (SQLite, ~25 МБ) из приложения `com.touchbytouch.recnik_android`
(«Serbian-Russian dictionary», версия 2.0.2).

Всё описанное ниже получено обратной разработкой самих данных: содержимое базы
разбиралось запросами и статистическим сопоставлением. Там, где вывод не стопроцентный,
это отмечено явно словами «предположительно» или «не проверено».

База открывается только на чтение:

```python
sqlite3.connect('file:/путь/srbbase.db?mode=ro', uri=True)
```

---

## 1. Обзор базы

Словарь построен вокруг одной большой таблицы словарных статей `words`
(45 633 строки) и двух вспомогательных таблиц обратного поиска — с русского
на сербский. Остальные таблицы принадлежат самому приложению (настройки,
избранное, история) и в поставке пусты.

Сербский текст хранится в двух видах одновременно:

* **латиница без знаков ударения** — в ключевых полях (`words.name`,
  `ruswords.srbname`). Это технический ключ поиска;
* **кириллица со знаками ударения** — внутри разметки статьи (`words.xml`)
  и в `rusref.srbname`. Это то, что видит пользователь.

Переход между ними — обычная сербская взаимно-однозначная транслитерация
(а→a, б→b, …, љ→lj, њ→nj, џ→dž, ђ→đ, ћ→ć, ж→ž, ч→č, ш→š). Проверено:
транслитерация первого фрагмента `xml` в латиницу совпадает с полем `stress`
для **всех 45 633 записей** (после удаления служебных `||`, см. раздел 8.3).

## 2. Таблицы и их назначение

### 2.1 `words` — словарные статьи (сербский → русский)

```sql
CREATE TABLE words (
  name   TEXT PRIMARY KEY NOT NULL,  -- заглавное слово, латиница, без ударений
  stress TEXT NOT NULL,              -- то же слово, латиница, со знаками ударения
  kw     TEXT,                       -- переводы через ';' — поисковый индекс
  xml    TEXT                        -- полный текст статьи в собственной разметке
)
```

45 633 строки. Ни одной строки с `xml IS NULL` или пустым `xml`.
`kw` пуст у 154 записей.

Примеры:

| name | stress | kw |
|---|---|---|
| `voda` | `vo‛da` | `вода’;река’` |
| `junak` | `ju‛na_k` | `геро’й;молоде’ц` |
| `mesec` | `me“se_c` | `ме’сяц;луна’;спу’тник плане’ты` |

Набор символов `name`: `A-Z a-z` (без `q w x y`), `ćČčĐđŠšŽž`, а также пробел,
дефис, запятая, точка и восклицательный знак (см. раздел 8.5).

### 2.2 `ruswords` — обратный указатель русский → сербский

```sql
CREATE TABLE ruswords (
  name    TEXT PRIMARY KEY NOT NULL, -- русское слово/оборот, без ударений
  stress  TEXT NOT NULL,             -- то же с ударениями (знак ’)
  srbname TEXT NOT NULL              -- сербские соответствия, КИРИЛЛИЦА, через ';'
)
```

47 920 строк. Пример:

```
('абажур', 'абажу’р', 'абажур;штит')
('ах!',    'ах!',     'а;авај!;аја!;ала;е;и;ју!;јуј!;куку!;ох!')
```

**Связь с `words`.** `srbname` — список через `;`; каждый элемент записан
**кириллицей без ударений**. Чтобы получить внешний ключ на `words.name`,
элемент надо транслитерировать в латиницу. Проверено: 110 753 из 110 833
элементов после транслитерации находятся в `words.name`; 80 «промахов» —
это элементы, где вместо `;` по ошибке стоит `|`
(`'бездана|вркнути'`, `'атлас|атлас'`, `'угаони|угљени'`). При разборе
разделителем стоит считать `[;|]`.

### 2.3 `rusref` — развёрнутая карточка обратного поиска

```sql
CREATE TABLE rusref (
  name    TEXT NOT NULL,   -- русское слово
  stress  TEXT NOT NULL,   -- русское слово с ударением
  srbname TEXT NOT NULL,   -- сербское слово, КИРИЛЛИЦА СО ЗНАКАМИ УДАРЕНИЯ
  kw      TEXT,            -- копия words.kw соответствующей сербской статьи
  PRIMARY KEY (name, stress, srbname)
)
```

13 510 строк, но всего **907 различных русских слов**. То есть это таблица не
для всех русских слов, а только для сильно многозначных, у которых десятки
сербских соответствий. Похоже, приложение показывает по такому слову
отдельный экран со списком «сербское слово + его переводы», чтобы
пользователь мог выбрать нужный оттенок.

Пример (`балда`, 13 сербских соответствий):

```
('балда', 'балда’', 'бе“дак',  'дура’к;глупе’ц;балда’')
('балда', 'балда’', 'бу’зда',  'балда’;дуби’на;наби’тый дура’к')
('балда', 'балда’', 'ти“ква',  'ты’ква;сосу’д из ты’квы;бу’бны;ду’рень;балда’')
```

**Связь с `words`.** `rusref.srbname` в транслитерации в латиницу равен
`words.stress` — совпадение **100 % (13 510 из 13 510)**. То есть это
внешний ключ не на `name`, а на `stress`. Поле `rusref.kw` совпадает с
`words.kw` в 13 507 случаях из 13 510 (три расхождения — вероятно,
устаревшие копии, конкретную причину не выяснял).

Все 907 русских слов из `rusref` присутствуют и в `ruswords`.

### 2.4 Служебные таблицы приложения

`setup`, `changes`, `favor` (избранное), `history` (история просмотров),
`sqlite_sequence`. Для переноса данных не нужны, в поставке пусты.
На `history` висит триггер, обрезающий её до 500 последних записей.

## 3. Поле `stress` — знаки ударения

Сербский язык имеет четыре тона-ударения плюс послеударную долготу.
В базе они закодированы обычными знаками препинания, которые ставятся
**после** гласной, к которой относятся.

### 3.1 Таблица соответствия

| Знак | Код | Название по-русски | Сербское название | Обычный знак | Пример из базы |
|---|---|---|---|---|---|
| `‛` | U+201B | краткое восходящее | kratkouzlazni | ◌̀ (`ù`) | `vo‛da` — vòda «вода» |
| `’` | U+2019 | долгое восходящее | dugouzlazni | ◌́ (`ú`) | `ru’ka` — rúka «рука» |
| `“` | U+201C | краткое нисходящее | kratkosilazni | ◌̏ (`ȕ`) | `bra“t` — brȁt «брат» |
| `^` | U+005E | долгое нисходящее | dugosilazni | ◌̑ (`ȗ`) | `ma^jka` — mȃjka «мать» |
| `_` | U+005F | послеударная долгота | postakcenatska dužina | ◌̄ (`ū`) | `ju‛na_k` — jùnāk «герой» |

Частотность в базе: `‛` 23 293, `_` 11 462, `’` 11 413, `“` 9 156, `^` 1 769.

### 3.2 Проверка на известных словах

Сверено с нормативной сербской акцентологией — **35 слов из 35 совпали**.
Уверенность в соответствии знаков: очень высокая (близко к достоверности).

Соответствие подтверждено **вторым, независимым способом** — структурным.
В сербском языке действует правило: **нисходящие ударения бывают только на первом
слоге**, восходящие же на первом слоге как раз стоять не обязаны. Считаем, на каком
слоге стоит знак:

| Знак | Всего | Не на первом слоге |
|---|---|---|
| `^` долгое нисходящее | 1 768 | 115 (6,5 %) |
| `“` краткое нисходящее | 9 127 | 561 (6,1 %) |
| `‛` краткое восходящее | 23 272 | 10 033 (43,1 %) |
| `’` долгое восходящее | 11 410 | 7 835 (68,7 %) |

Знаки `^` и `“` ведут себя как нисходящие, `‛` и `’` — как восходящие, ровно по правилу.
Оставшиеся 6 % — сложные и заимствованные слова, для которых это правило и так
не выполняется. Разделение «краткое / долгое» подтверждается частотностью: краткое
нисходящее (9 127) встречается заметно чаще долгого (1 768), как и в языке.

|---|---|---|---|

Обратите внимание: знак долготы `_` всегда стоит **после** знака тона в слове
(тон на ударном слоге, долгота — на последующем). Случаев, когда `_`
предшествует знаку тона, всего 22 из 45 633 — это сочетание `“‛_`
(два ударения в составном слове), где `_` относится ко второму тону.
Отдельно стоящий `_` без всякого тона встречается 18 раз (вероятно, ошибки данных).

### 3.3 Грамматика поля `stress`

```
stress   ::= слово ( разделитель слово )*
слово    ::= ( буква | тон? | долгота? )+
тон      ::= '‛' | '’' | '“' | '^'
долгота  ::= '_'
разделитель ::= ' ' | '-' | ',' | '.' | '!'
буква    ::= [A-Za-z] минус q,w,x,y  |  ć Č č Đ đ Š š Ž ž
```

Распределение количества знаков тона на запись:

| Знаков тона | Записей |
|---|---|
| 0 | 156 |
| 1 | 45 324 |
| 2 | 152 |
| 3 | 1 |

Слово **может** иметь больше одного знака тона — это составные слова
(`a“vr_lj-ba“vr_lj`, `di^n-du‛šmanin`) и составные заглавные единицы
из нескольких слов. 156 записей вообще без тона — среди них есть безударные
служебные слова (`oko` в значении предлога) и, по-видимому, просто пропуски
в данных.

Самые частые последовательности знаков: `‛` (16 758), `’` (10 725),
`“` (6 089), `‛_` (5 633), `“_` (2 734), `^` (1 450), `‛__` (773).
Долгота может повторяться до трёх-четырёх раз (`‛___`, 20 записей) —
на нескольких послеударных слогах.

Многословные заглавные единицы есть: 1 472 записи с пробелом в `name`,
почти все — возвратные глаголы вида `akati se`, `baviti se`.
Отдельных предлогов-проклитик как заглавных единиц с переносом
ударения в базе нет.

## 4. Грамматика разметки `xml`

Название поля вводит в заблуждение: это **не XML**. Это плоский поток
фрагментов текста, каждый со своей пометой класса.

### 4.1 Базовая структура

```
xml      ::= фрагмент*
фрагмент ::= текст [ '$' тег ] '#'
```

Разделитель фрагментов — символ `#`. Если во фрагменте есть `$`, то всё
после последнего `$` — это тег; тег может быть **пустым** (`текст$#`),
и пустой тег — значимый (см. ниже). Если `$` нет, у фрагмента нет тега вовсе.

Пример полностью разобранной короткой статьи (`kuca`):

```
ку’ца$C#ж$#.#соба’чка$RV#,#пёсик$RV#.#
```

| Текст | Тег | Смысл |
|---|---|---|
| `ку’ца` | `C` | заглавное слово (кириллица, с ударением) |
| `ж` | *(пустой)* | грамматическая помета «женский род» |
| `.` | *(нет)* | знак препинания |
| `соба’чка` | `RV` | перевод |
| `,` | *(нет)* | знак препинания |
| `пёсик` | `RV` | перевод |
| `.` | *(нет)* | конец статьи |

### 4.2 Таблица тегов

Частотность по всей базе:

| Тег | Кол-во | Значение | Уверенность |
|---|---|---|---|
| *(нет `$`)* | 290 807 | знаки препинания и скобки между фрагментами | высокая |
| `RV` | 133 022 | **русский перевод** заглавного слова (попадает в `kw`) | высокая |
| *(пустой, `$#`)* | 112 284 | **прочий русский текст**: грамматические пометы, римские цифры, пояснения в скобках, перевод примеров | высокая |
| `C` | 105 889 | **сербский текст** (кириллица) — заглавное слово, формы, примеры | высокая |
| `CL` | 33 240 | **сербский текст — ссылка** на другую статью словаря | высокая |
| `D` | 32 082 | **номер значения** (цифра перед `)`) | высокая |
| `PC` | 6 314 | знак препинания внутри сербского фрагмента | высокая |
| `MC` | 3 292 | то же, что `C`, но фрагмент содержит примыкающую пунктуацию | средняя |
| `PRV` | 3 199 | знак препинания внутри русского фрагмента | высокая |

| `MRV` | 965 | то же, что `RV`, с примыкающей пунктуацией | средняя |
| `SC` | 51 | символ `◊` в сербском контексте | средняя |
| `DC` | 25 | число в сербском контексте | средняя |
| `MCL` | 17 | `CL` с примыкающей пунктуацией | средняя |
| `N` | 14 | «прочее» — по сути мусор/опечатки в исходных данных | средняя |
| `DRV` | 6 | число в русском контексте | средняя |
| `NC` | 2 | «прочее» в сербском контексте | низкая |

### 4.3 `C` против `CL` — гиперссылки

Проверка: если взять текст фрагмента, снять знаки ударения и `~`,
транслитерировать в латиницу и поискать в `words.name`:

| Тег | Нашлось | Не нашлось | Доля |
|---|---|---|---|
| `CL` | 32 950 | 290 | **99,1 %** |
| `C` | 65 836 | 40 053 | 62,2 % |

Причём почти все 290 «промахов» `CL` — это заглавные слова со знаками
ударения и служебным `||` (например `а‛драповск||и_`), то есть тоже
ссылки, просто на форму с ударением.

Вывод: **`CL` = слово, на которое приложение делает переход в другую статью.
`C` = обычный сербский текст.** 62 % совпадений у `C` — случайность:
многие словоформы совпадают с чужими заглавными словами.

Самое наглядное подтверждение — отсылочные статьи, где после «см.» стоит
именно `CL`:

```
ку’ца ... ру“ка$C#II$#ж$#.#см$#.#рика$CL#.#
```

Внутри примера ссылками помечены ровно те слова, которые есть в словаре
как отдельные статьи:

```
не$CL#може$C#да$CL#говори$C#
```
(`не`, `да` — есть в словаре; `може`, `говори` — словоформы, статей нет).

### 4.4 Префикс `M`

Проверено на всей базе: фрагмент помечен `M…` **тогда и только тогда**,
когда его текст содержит небуквенный символ (кроме знаков ударения,
`~` и `|`). Совпадение: 7 358 фрагментов `M…` — все «смешанные»,
и ни одного «смешанного» без `M`, кроме 3 080 случаев многословных
фрагментов с пробелом (например `а“кати се`).

Примеры: `кого’-$M#`, `по-$M#`, `«нале’во»$M#`, `-тује_м$MC#`, `а!$MRV#`,
`шта$CL#радите?$MC#`.

Предположительно `M` — подсказка для отрисовки («не вставлять пробел /
не разбивать»), а не смысловая помета. **Для переноса данных `M…`
следует трактовать точно так же, как соответствующий базовый тег**
(`MC`→`C`, `MCL`→`CL`, `MRV`→`RV`, `M`→пустой).

### 4.5 Редкие теги

* `SC` (51) — символ `◊` перед сербским текстом; в остальном то же, что `S`:
  `◊$SC#~$C#-$PC#салата$CL#баклажа’нная$#икра’$#`
* `DC` (25) — число внутри сербской фразы: `~$PC#има$C#24$DC#часа$C#`
* `DRV` (6) — число внутри русского перевода: `моне’та$RV#в$RV#2$DRV#дина’ра$RV#`
* `N` (14), `NC` (2) — похоже на ошибки набора: `2!$N#покрови’тель$RV#`
  (должно быть `2$D#)$#`), `1)$N#переста’ть$RV#`, `≈$N#` (должно быть `$S#`),
  `3-$N#го$#`, `10%$N#`. Обрабатывать как «текст без класса».

### 4.6 Значения фрагментов без тега

| Символ | Кол-во |
|---|---|
| `.` | 99 111 |
| `,` | 72 706 |
| `)` | 49 760 |
| `;` | 49 744 |
| `(` | 17 507 |
| `-` | 1 370 |
| `:` | 491 |
| `!` | 40 |
| `@` | 30 |
| `?` | 22 |

Прочие (`]`, `[`, `%`, `\`, `/`, `}`, `…`, `.»`, `);`) — единичные, шум.

Символ `@` — **разрыв абзаца**, встречается в 16 статьях. Двойной `@#@#`
отделяет омонимичные блоки друг от друга (`gora`, `era`, `zbiti`),
одиночный `@#` — новую строку внутри статьи (`na`, `po`, `u`, `pod`,
где так отделены блоки «с таким-то падежом»).

## 5. Как выделять значения, переводы и примеры

### 5.1 Общий скелет статьи

```
[заглавное слово $C#] [ , $C# доп. форма ]*
[римская цифра $#]            -- омоним, необязательно
[грамматические пометы $# + . ]*
  для каждого значения:
    [номер $D#] [ ) ]
    [стилистические пометы $# + . ]*
    перевод$RV# [ , | ; перевод$RV# ]*
    для каждого примера:
      сербская фраза: цепочка $C# / $CL# / $PC#
      русский перевод примера: цепочка $# / $M# / $PRV#
[◊ $S#]                        -- начало блока устойчивых оборотов
  обороты в том же формате «сербская фраза → русский перевод»
[.]
```

### 5.2 Значения (разные смыслы слова)

Разделитель — фрагмент с тегом **`D`** (или `DC`), содержащий цифру,
за которым идёт фрагмент `)`:

```
1$D#)#гора’$RV#;#2$D#)#лес$RV#.#
```

Распределение количества значений (максимальный номер `D` в статье):

| Значений | Статей |
|---|---|
| 0 (нумерации нет) | 32 734 |
| 2 | 9 950 |
| 3 | 2 165 |
| 4 | 510 |
| 5 | 145 |
| 6 и больше | ~50 |

**Важно: в 32 734 статьях (72 %) нумерации значений нет вообще.**
Это значит, что разные переводы там либо синонимы одного значения,
либо разные значения, никак не разграниченные. Автоматически разделить
их нельзя — разве что по разделителю `;` (см. ниже), но это лишь
приблизительно.

У 49 статей максимальный номер `D` равен 1 — то есть нумерация начата и
брошена; это опечатки, надо быть готовым.

Есть также вложенная нумерация: в статьях-предлогах (`na`, `po`, `u`, `pod`, `s`)
верхний уровень — падеж (`1$D#.#с$#местн$#.#п$#.#`), нижний — значение
(`1$D#)#`). Обе используют один и тот же тег `D`, различаются только тем,
что за фрагментом идёт `.` или `)`. **Это надёжный, но нетривиальный
частный случай — обрабатывать отдельно.**

### 5.3 Переводы внутри значения

Переводы — это фрагменты с тегом **`RV`**. Идущие подряд `RV`-фрагменты
образуют один многословный перевод (`портно’й` `шью’щий` `из` `абы’`).
Разделители между ними:

* `,` (без тега) — близкие синонимы;
* `;` (без тега) — более далёкие оттенки.

Поле `kw` — это ровно склейка `RV`-фрагментов через `;`. Проверка:
простое правило «группы `RV`, разделённые чем угодно, склеенные через `;`»
даёт точное совпадение с `kw` для **38 875 записей из 45 633 (85 %)**.
Из 6 758 расхождений:

* **3 344** — статьи, где `RV`-фрагментов нет вообще, но `kw` заполнено
  (отсылочные статьи, см. 8.2). Всего статей без `RV`-фрагментов — 3 498;
* **2 234** — случаи, где запятая осталась **внутри** элемента `kw`
  (`портно’й, шью’щий из абы’`), то есть автор счёл это одним переводом.

Однозначного правила, когда запятая разрывает перевод, а когда нет, по самой разметке
`xml` найти не удалось.

**Но вопрос закрывается полем `kw`.** Проверено на всех статьях, где есть и `kw`,
и хотя бы один фрагмент `RV`:

| Соотношение | Статей |
|---|---|
| элементов в `kw` **меньше**, чем групп `RV` | 2 997 |
| элементов в `kw` **больше**, чем групп `RV` | **0** |
| поровну | 39 138 |

Ни одного случая, когда `kw` дробит перевод мельче, чем разметка. То есть `kw`
относительно группировки по `RV` умеет только **склеивать** (там, где границей была
запятая), но никогда не разрезает лишнего.

**Практический вывод: границы переводов брать из `kw`, а не из `xml`.** `kw` —
более авторитетный источник по этому вопросу, а разметка `RV` избыточно дробит
переводы по запятой. `xml` при этом остаётся источником всего остального
(значения, примеры, пометы, фразеология).

### 5.4 Примеры употребления

Пример = **непрерывная цепочка сербских фрагментов** (`C`/`CL`/`MC`/`MCL`/`PC`),
за которой идёт **непрерывная цепочка русских фрагментов с пустым тегом**
(`$#`/`$M#`/`$PRV#`). Ключ к разделению: перевод самого слова помечен `RV`,
а перевод примера — пустым тегом.

```
слатка$C#~а$C#пре’сная$#вода’$#;#
```
→ сербский: «слатка ~а» = *slatka voda*; русский: «пресная вода».

```
иде$C#~а$C#на$CL#уста$CL#слю’нки$#теку’т$#;#
```
→ «иде вода на уста» — «слюнки текут».

Примеры отделяются друг от друга фрагментом `;`.

**Это правило надёжно** — сама разметка построена именно на нём. Единственный
подводный камень: римские цифры омонимов (`I`, `II`, `III`) и грамматические
пометы тоже идут с пустым тегом, поэтому цепочку «русского перевода примера»
надо начинать только после сербской цепочки.

### 5.5 Устойчивые обороты и идиомы

Фрагмент `◊$S#` (или `◊$SC#`) открывает блок фразеологии — дальше до конца
статьи идут устойчивые обороты в формате «сербская фраза → русский перевод».
Статей с `◊`: 2 097.

Фрагмент `≈$S#` (352 статьи) означает «приблизительно соответствует»,
ставится перед русским эквивалентом, который не является дословным переводом:

```
тиха$C#~а$C#брег$CL#рони$C#посл$#.#≈$S#в$#ти’хом$#о’муте$#че’рти$#во’дятся$#
```

**Важно: переводы внутри блока `◊` помечены пустым тегом, а не `RV`,**
и поэтому не попадают в `kw`. То есть фразеологию нельзя искать по `kw`.

прилагательные, где часть речи задаётся **структурно**, набором форм:

* **Глагол** — заглавное слово + запятая + форма 1 л. ед. ч. наст. вр.

  — **12 254**.

  формы `~ни_`, `~на`, `~но`:


  (реальное число больше: форма среднего рода не всегда `~но`).

помет недостаточно, нужен комбинированный алгоритм —
(1) явная помета `м`/`ж`/`с`/`нареч`/`мест`/`межд`/`числит`/`прил`;
(2) `сов`/`несов`/`многокр` → глагол;
(3) структурный признак «вторая форма на `-м`» → глагол;
(4) структурный признак «три формы `~…`» → прилагательное;
(5) `см` в начале и отсутствие всего остального → отсылочная статья,
    часть речи брать из целевой статьи.

## 7. Условные обозначения внутри текста статьи

### 7.1 `||` — граница основы

В заглавном слове `||` отделяет неизменяемую основу от окончания:

```
во‛д||а   → основа «вод», окончание «а»
ру’к||а   → основа «рук»
су^нц||е  → основа «сунц»
```

Встречается в 7 607 статьях. Символ чисто служебный, при отображении убирается.

### 7.2 `~` — повтор заглавного слова

Тильда заменяет:

* **основу** (часть до `||`), если `||` есть:
  ```
  во‛д||а ... слатка$C#~а$C#   →  «слатка вода»
  ру’к||а ... из$CL#~у$C#у$CL#~у$C#  →  «из руку у руку»
  ```
* **всё заглавное слово**, если `||` нет:
  ```
  би“ти ... ~$C#вољан$CL#  →  «бити вољан»
  ра’дити ... ~$C#се$CL#   →  «радити се»
  ```

### 7.3 Римские цифры — омонимы

`words.name` — первичный ключ, поэтому **все омонимы упакованы в одну
строку**. Разделяются римскими цифрами с пустым тегом.

1 658 статей содержат римские цифры. Распределение:

| Последовательность | Статей |
|---|---|
| `I`, `II` | 1 072 |
| только `I` | 220 |
| только `II` | 131 |
| `I`, `II`, `III` | 84 |
| `I`, `I`, `II`, `II` | 72 |
| прочие | ~80 |

Пример статьи `a` (три омонима в одной строке):

```
а$C#I$#союз$#1$D#)#...  ◊$S#а$C#то$CL#... 
а‛$C#II$#а‛а_!$MC#межд$#.#а!$MRV#,#ах!$MRV#;#ах$RV#так!$MRV#
а$C#III$#а‛-а_!$MC#межд$#.#отрицат$#.#нет!$M#;#а-а!$MC#нећу$C#jа$C#то$CL#нет$#,#не$#хочу’$#я$#э’того$#.#
```

Здесь один ряд `words` содержит три полноценные словарные статьи:
союз, междометие «а!» и междометие отрицания «а-а!».

Пример `biti` — два разных глагола (быть / бить):

```
би“ти$C#I$#,#бу“де_м$C#(#је‛сам$C#)#быть$RV#;#◊$S#...
би“ти$C#II$#,#би“је_м$C#1$D#)#бить$RV#,#колоти’ть$RV#;#...
```

Обратите внимание: `stress` при этом хранит **только первый вариант**
(`bi“ti`), хотя у омонимов может быть разное ударение
(`го‛ра` и `го“ра` в статье `gora`). **Это потеря информации на уровне
схемы.**

Последовательности вида `I I II II` (72 статьи) — это когда римские цифры
относятся не к омонимам текущего слова, а к ссылкам на омонимы других слов
(`см$#.#Ера$CL#II$C#`). Различать их надо по контексту: цифра сразу после
`CL`-фрагмента — часть ссылки, цифра после `C`-фрагмента-заголовка —
номер омонима. **Здесь возможны ошибки разбора, надёжного признака
не найдено.**

## 8. Известные сложности и краевые случаи

### 8.1 Свойства статьи, на которые можно опираться

* Первый фрагмент **всегда** `C` (45 543) или `MC` (90). Иных вариантов нет.
* Транслитерация первого фрагмента (после удаления `||`) **всегда**
  равна `stress` — 45 633 из 45 633.
* Последний фрагмент — `.` без тега в 45 493 случаях из 45 633.
  Остальное — `!`, `?`, `.$PRV#` и несколько фрагментов `M`.

### 8.2 Отсылочные статьи

4 901 статья содержит `см$#.#`. Чисто отсылочные статьи выглядят так:

```
а‛банос$C#м$#.#см$#.#абонос$CL#.#
ава’нса$C#ж$#.#см$#.#аванс$CL#.#
аванту‛риста$C#м$#.#см$#.#авантурист$CL#.#
```

У них **нет ни одного фрагмента `RV`**, но `kw` заполнено — переводы
скопированы из целевой статьи (`abanos` → `чёрное де’рево;эбе’новое де’рево`).
Всего таких «`kw` без `RV`» — 3 344.

Вывод: **`kw` нельзя выводить из `xml`, это независимый источник данных.**
При переносе надо либо хранить `kw` как есть, либо явно раскрывать отсылки.

Существует и помета `ср$#.#` — «сравни», мягкая отсылка, не заменяющая статью.

### 8.3 Кодировка и символы

* Всё в UTF-8, аномалий не обнаружено.
* Русское ударение — `’` (U+2019), тот же символ, что и сербское долгое
  восходящее. **Один и тот же символ означает разное в сербском и русском
  тексте.** Различать только по тегу фрагмента (`C`/`CL` = сербский,
  `RV`/пустой = русский).
* Символ `“` (U+201C) — это знак ударения, а не открывающая кавычка.
  Настоящие кавычки в тексте — «ёлочки» (`«нале’во»`).
* В сербской латинице отсутствуют буквы `q`, `w`, `x`, `y`.
* Диграфы `lj`, `nj`, `dž` при транслитерации из кириллицы дают два-три
  символа — обратная транслитерация из латиницы неоднозначна
  (`nj` может быть `њ` или `нј`). **Направление «латиница → кириллица»
  без словаря ненадёжно; в базе оно, к счастью, не требуется.**

### 8.4 Ошибки и мусор в данных

* Теги `N`/`NC` (16 фрагментов) — опечатки набора.
* Разделитель `|` вместо `;` в `ruswords.srbname` (80 случаев).
* Одиночный знак долготы `_` без знака тона (18 записей `stress`).
* Максимальный номер значения `1` (49 статей) — брошенная нумерация.
* Единичные символы `\`, `/`, `}`, `[`, `]`, `%` как фрагменты без тега.
* Опечатка в данных: `испљјувак` (в `ruswords.srbname` для «мокрота») —
  такого слова в `words` нет.

### 8.5 Странности в `name`

`words.name` содержит не только буквы:

* восклицательный знак — междометия: `avaj!`, `ais!`, `aj!`, `aman!`, `ao!`;
* дефис — сложные слова: `avrlj-bavrlj`, `amo-tamo`, `andara-mandara`,
  `apa-drapa`, `austro-ugarski`;
* многоточие — префиксы: `arhi...`;
* пробел — 1 472 многословных единицы, в основном возвратные глаголы
  (`baviti se`, `akati se`);
* заглавные буквы — имена собственные (`Abisinac`, `Bečlija`, `Ero`, `Ера`).

### 8.6 Сводка рисков переноса данных

1. **Омонимы схлопнуты в одну строку.** `words.name` — первичный ключ,
   поэтому 1 658 строк содержат по 2–4 самостоятельные статьи, а поле
   `stress` хранит ударение только первой из них. Разбор по римским
   цифрам обязателен и не полностью надёжен (см. 7.3).
2. **72 % статей не имеют нумерации значений.** Разделить их на значения
   автоматически невозможно; придётся либо считать всю статью одним
   значением, либо резать по `;` с потерей точности.
3. **`kw` не выводится из `xml`.** У 3 344 отсылочных статей переводы
   есть только в `kw`. Само по себе это не риск, а указание: `kw` —
   независимый и более авторитетный источник границ переводов (см. 5.3),
   хранить его надо обязательно.
4. **Фразеология после `◊` размечена как обычный текст**, а не как
   перевод (`RV`), и в `kw` не попадает. Если её не обработать отдельно,
   2 097 статей потеряют самую ценную часть.
5. **Часть речи в трети статей задана только структурно** — набором форм,
   а не пометой. Нужен комбинированный алгоритм (см. 6.2), словаря
   сокращений недостаточно.

```python
def chunks(xml: str) -> list[tuple[str, str | None]]:
    """Разбирает поле words.xml на список (текст, тег).

    тег == None  -> фрагмент без '$' (знак препинания);
    тег == ''    -> фрагмент с пустым тегом (русский текст, пометы);
    иначе        -> 'C', 'CL', 'RV', 'D', 'S', 'PC', 'PRV', 'M...' и т. д.
    """
    out = []
    for part in xml.split('#'):
        if part == '':
            continue
        i = part.rfind('$')
        out.append((part[:i], part[i + 1:]) if i >= 0 else (part, None))
    return out
```
